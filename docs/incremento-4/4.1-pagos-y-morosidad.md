# 4.1 Pagos, abonos y control de morosidad

**Incremento 4:** Pagos, abonos y control de morosidad
**Responsable:** Sánchez Jimenes Jaret Isai
**Basado en:** [2.1 Diseño de la base de datos](../incremento-2/2.1-diseno-base-de-datos.md) y [3.1 Solicitudes y aprobación](../incremento-3/3.1-solicitudes-y-aprobacion.md)
**Requisitos:** RF59, RF61, RF64–RF81, RF113, RF116, RNF26, RNF27

Cubre las tareas 4 a 4.6: registro de pagos y abonos, cálculo del saldo, control de vencimientos,
identificación de morosos, alertas y reportes de pagos.

## 1. Cambios en la base de datos (migración `0006_moras`)

El diseño 2.1 dejó las moras para este incremento. Se agregan sin modificar las tablas existentes:

```sql
CREATE TABLE moras (
  id                  VARCHAR(36) PRIMARY KEY,
  credito_id          VARCHAR(36) NOT NULL REFERENCES creditos (id),
  semana              INTEGER     NOT NULL,
  monto_centavos      BIGINT      NOT NULL CHECK (monto_centavos > 0),  -- mora semanal del crédito
  pagado_centavos     BIGINT      NOT NULL DEFAULT 0,
  condonado_centavos  BIGINT      NOT NULL DEFAULT 0,                   -- RF79
  generada_en         BIGINT      NOT NULL,
  UNIQUE (credito_id, semana),
  CHECK (pagado_centavos >= 0 AND condonado_centavos >= 0
         AND pagado_centavos + condonado_centavos <= monto_centavos)
);

-- Parte de cada pago que cubrió mora (el resto se aplicó al saldo)
ALTER TABLE operaciones ADD mora_centavos BIGINT NOT NULL DEFAULT 0;
```

La mora se lleva **aparte del saldo**: el saldo del crédito sigue siendo capital más interés (RF59), y
la mora pendiente es la suma de `monto − pagado − condonado`.

## 2. Reglas de negocio

| ID | Regla |
| --- | --- |
| RN-40 | **Pago o abono** (RF64–RF68): el monto se reparte de la semana más antigua sin cubrir en adelante. Si la última semana que toca queda completa es **pago**; si queda a medias es **abono**. Un pago mayor que una semana cubre las siguientes. |
| RN-41 | **Mora** (RF73–RF75): cada semana que vence sin cubrirse por completo genera **una** mora igual a la mora semanal del crédito. Vence el día indicado: pagar ese mismo día no genera mora. |
| RN-42 | Las moras se generan al consultar el crédito y antes de aplicar cualquier pago. Como toda semana se cubre con un pago, ninguna semana atrasada se escapa sin su mora, sin necesidad de una tarea programada. |
| RN-43 | **Orden de aplicación** (RF76): el pago cubre primero la mora pendiente (de la más antigua a la más reciente) y después las semanas. |
| RN-44 | Un pago no puede ser mayor que el adeudo total (saldo + mora pendiente). Si deja el saldo en cero, el crédito se liquida (Incremento 5). |
| RN-45 | **Condonación** (RF79): solo el Gerente, con motivo, perdona toda la mora pendiente de un crédito vigente de sus Cobradores. No cambia el saldo. |
| RN-46 | **Días de atraso**: desde el vencimiento más antiguo sin cubrir. **Nivel de morosidad** (RF77, RF78): al corriente (0), atraso (1–7 días), moroso (8–29) y cartera vencida (30 o más). |
| RN-47 | Si dos personas registran un movimiento del mismo crédito al mismo tiempo (incluso un pago solo de mora, que no cambia el saldo), el segundo recibe un aviso para recargar (RNF05). |
| RN-24 | Cada pago lleva una clave de idempotencia generada al abrir la ventana: un reenvío muestra el comprobante del pago ya guardado y no lo duplica. |

### Cómo se garantiza que nada quede a medias

Cada pago es un solo `db.batch()`: guarda las moras que falten, toma el folio `OP-000001`, inserta la
operación **solo si el crédito sigue como se leyó** (mismo estado, saldo y última modificación) y,
solo si la operación se guardó, actualiza saldo, semanas, moras pagadas y bitácora. Si otra persona se
adelantó, ninguna consulta cambia nada y la API responde 409.

**Acciones nuevas en la bitácora:** `pago_registrado`, `mora_condonada`.

## 3. Cobranza, alertas y reportes

| Tarea | Pantalla | Qué muestra |
| --- | --- | --- |
| 4.3, 4.4 Vencimientos y morosos | **Cobranza** (`/cobranza`) | Créditos vigentes con próximo vencimiento, semanas vencidas, mora, días de atraso y lo que hay que cobrar hoy para dejar al cliente al corriente. Filtros: cobrar hoy, atrasados, esta semana, todos. Se calcula con dos consultas agrupadas, sin leer el calendario de cada crédito. |
| 4.5 Alertas (RNF26, RNF27) | **Inicio** | Créditos atrasados (y cuántos con 8 días o más), monto a cobrar hoy, solicitudes pendientes y créditos por desembolsar. |
| 4.6 Reportes de pagos (RF80) | **Reportes → Pagos** y **Morosidad** (`/reportes`) | Pagos, abonos y liquidaciones de un periodo, con total cobrado, mora cobrada y totales por Cobrador; créditos atrasados por nivel de morosidad. Descarga en CSV para Excel. |

Cada rol ve lo de su ámbito: el Cobrador, sus créditos; el Gerente, los de sus Cobradores; el
Administrador, todos (solo consulta).
